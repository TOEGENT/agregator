# Структура БД

Каждый парсер сохраняет собственную БД в pickle, а отдельный сборщик объединяет их в одну итоговую БД. Во всех файлах используются три словаря: `catalogs`, `cards` и `reverse`.

## Итоговая объединённая БД

```python
db = {
    "catalogs": {
        "root": {
            "title": "Каталог",
            "children": [
                "fundamentbolt", "csk66", "td-svarka",
                "provent", "zavkrov", "metallotorg",
            ],
            "parents":[]
        },
        "provent": {
            "title": "Вентиляция",
            "dealer": "Provent",
            "children": ["provent:5428"],
            "parents":["root"]
        },
    
        "provent:5428": {
            "title": "Вентиляторы",
            "children": ["provent:5440"],
            "parents": ["root","provent"]
        },
        "provent:5440": {
            "title": "Канальные вентиляторы",
            "children": ["provent:card:12345"],
            "parents": ["root","provent","provent:5428"]
        },
    },
    "cards": {
        "provent:card:12345": {
            "name": "Канальный вентилятор",
            "images": ["image.webp"],
            "description": "Описание товара",
            "stats": {"Производительность": "500 м³/ч"},
            "parents": ["root","provent","provent:5428","provent:5440"]
        },
    },
    "reverse": {
        "fundamentbolt": "root",
        "csk66": "root",
        "td-svarka": "root",
        "provent": "root",
        "zavkrov": "root",
        "metallotorg": "root",
        "provent:5428": "provent",
        "provent:5440": "provent:5428",
        "provent:card:12345": "provent:5440",
    },
}
```

Корневые разделы итоговой БД:

| ID | `title` | `dealer` | Исходный файл |
| --- | --- | --- | --- |
| `fundamentbolt` | Фундаментные болты | Fundamentbolt | `fundamentbolt.pkl` |
| `csk66` | Метизы, абразивы, такелаж | CSK66 | `csk66.pkl` |
| `td-svarka` | Сварка | ТД Сварка | `td-svarka.pkl` |
| `provent` | Вентиляция | Provent | `provent.pkl` |
| `zavkrov` | Кровля | Завод Кровля | `zavkrov.pkl` |
| `metallotorg` | Металл | Металлоторг | `metallotorg.pkl` |

## БД отдельного парсера

В отдельном pickle сохраняется обычное дерево с локальными ID. Его `root` содержит название раздела и поставщика:

```python
db = {
    "catalogs": {
        "root": {
            "title": "Вентиляция",
            "dealer": "Provent",
            "children": ["5428"],
        },
        "5428": {
            "title": "Вентиляторы",
            "children": ["card:12345"],
        },
    },
    "cards": {
        "card:12345": {
            "name": "Канальный вентилятор",
            "images": ["image.webp"],
            "description": "Описание товара",
            "stats": {},
        },
    },
    "reverse": {
        "5428": "root",
        "card:12345": "5428",
    },
}
```

## Правила

- `catalogs[id]["children"]` содержит ID только непосредственных потомков.
- У промежуточного каталога потомками являются подкаталоги, у конечного — карточки.
- Название не используется как ID, потому что названия могут повторяться.
- В отдельной БД каталог использует стабильный ID поставщика, а карточка имеет префикс `card:`.
- При объединении каждый локальный ID получает префикс источника: `5428` превращается в `provent:5428`, а `card:12345` — в `provent:card:12345`.
- Префикс источника обязателен: внутренние ID разных поставщиков могут совпадать.
- `dealer` обязателен у корня отдельной БД и у корневого раздела объединённой БД; во вложенных каталогах он не дублируется.
- Данные карточки всегда содержат `name`, `images`, `description` и `stats`.
- `reverse[child_id] = parent_id` хранит обратную связь для каждого каталога и каждой карточки, кроме общего `root`.
- Поиск проходит только по `cards.items()` объединённой БД.
- URL каталогов и карточек нужны только парсеру и в pickle не сохраняются; URL изображений остаются в `images`.

## Сборка

1. Каждый парсер формирует собственные `catalogs`, `cards` и `reverse` с локальным `root`.
2. Сборщик создаёт новый общий `root`.
3. Локальный `root` каждой БД превращается в корневой раздел с ID источника, например `provent`.
4. Всем остальным ID добавляется префикс источника.
5. Сборщик обновляет `children` и `reverse` с учётом новых ID.
6. Карточки копируются без изменения данных, меняются только их ключи.
7. Итоговые `catalogs`, `cards` и `reverse` сохраняются в общий pickle.

Пример восстановления пути найденной карточки:

```text
provent:card:12345 -> provent:5440 -> provent:5428 -> provent -> root
Канальный вентилятор -> Канальные вентиляторы -> Вентиляторы -> Вентиляция -> Каталог
```
